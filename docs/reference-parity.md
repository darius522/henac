# Legacy high-band reference parity

This record compares the original `entropy_ctrl_hb` implementation, the
consolidated model, and the supplied MUSHRA audio.

## Reference material

- Code: `entropy_ctrl_hb` at `1ae98408549d4e1d895d85d21124524ef634f97d`.
- Weights: `checkpoints/300k/dac/weights.pth`, SHA-256
  `4e511c753eeed87d251bc0e6d33f5e50dc8be0cd135570c6b3acd92db2cdc526`.
- Model configuration: `checkpoints/conf.yaml`, SHA-256
  `07e8e40956949894ef2c0bf391b08ed0637d7635ada64c32f528fe878722964c`.
- Inputs: 39 ten-second WAVs in `checkpoints/mushra/input`.
- Gold outputs: matching WAVs in
  `checkpoints/mushra/output_[16, 4, 2]_23kbps_wild`.

The script also checks SHA-256 manifests of the input and gold sets:
`7e26cf03c60a4a74e8b0b4327f51cff260f6750cbc98d7d496a4578c7c071962`
and `cca25ace0ed80a47f1b113baab485365998a52e88ad2ae3bbf093c87fb13683d`,
respectively. Each manifest hashes the newline-separated SHA-256 values of
the WAVs sorted by filename.

The checkpoint and MUSHRA files are local, untracked assets. A public parity
check will need these assets distributed separately.

## Reproduce

Use a CUDA environment with the legacy branch's model dependencies. From the
`master` checkout:

```bash
git worktree add --detach ../henac-hb 1ae98408549d4e1d895d85d21124524ef634f97d
python scripts/verify_mushra_reference.py \
  --reference-root ../henac-hb \
  --checkpoint-root checkpoints \
  --output-dir /tmp/henac-reference-output
```

The check loads the weights strictly, runs the branch's `DAC.infer_bands` with
`[16, 4, 2]` codebooks, filters its three decoder paths with Julius
`SplitBands(32000, [3000, 6200])`, sums the selected bands, and writes stereo
PCM16 WAVs. It disables cuDNN TF32 because enabling it causes much larger
differences from the gold audio on the checked A100 runtime.
The `henac-infer` command applies these CUDA settings automatically. Python
callers using `henac.inference` directly must set them when reproducing this
reference result.

## Measured baseline

On an NVIDIA A100 with PyTorch `2.11.0+cu130` and cuDNN TF32 disabled:

| Measure | Result |
| --- | ---: |
| Matched input/output files | 39 / 39 |
| Mean fraction of identical PCM samples | 99.688% |
| Lowest fraction of identical PCM samples | 98.870% |
| Lowest signal-to-difference ratio | 47.96 dB |
| Files differing by at most one PCM step throughout | 35 / 39 |

The four larger differences are confined to short regions:

| File | Region | Largest PCM difference |
| --- | ---: | ---: |
| `031474_chunk_0.wav` | 4.5419–4.6220 s | 1108 steps |
| `031474_chunk_1.wav` | 3.4642–3.4776 s | 91 steps |
| `064216_chunk_0.wav` | 3.9420–3.9522 s | 47 steps |
| `148516_chunk_1.wav` | 5.0286–5.1092 s | 2402 steps |

This establishes close waveform parity, not bit-exact reproduction. The
original source FMA WAVs and training-time software environment are not in
this workspace, so the cause of the four local differences is unconfirmed.
Changing cuDNN benchmark and deterministic settings did not remove them.
Two full runs on the checked runtime generated byte-identical WAV files.

## Consolidated model result

The consolidated model loads every weight key strictly from the 300k
checkpoint. Running `scripts/verify_checkpoint_parity.py` on the same A100
environment regenerated all 39 WAVs. The resulting PCM files are byte
identical to the legacy branch's regenerated files in
`/tmp/henac-parity-final`. Against the supplied gold files, the mean exact
sample fraction is 99.688%, the minimum is 98.870%, and the minimum
signal-to-difference ratio is 47.96 dB. The discrepancy from gold is therefore
already present in the legacy baseline on this software environment.

```bash
python scripts/verify_checkpoint_parity.py \
  --checkpoint-root checkpoints \
  --output-dir /tmp/henac-consolidated-parity \
  --legacy-output-dir /tmp/henac-parity-final
```

The legacy output directory is optional; omitting it checks only against gold.
The checker verifies hashes for the local weights, configuration, inputs, and
gold outputs before running. Its output log for this run is
`/tmp/henac-consolidated-parity.log`.

A separate spot check reconstructed `001662_chunk_0.wav` with all six supplied
codebook settings from `[16, 1, 0]` through `[16, 4, 2]`. Every output
differed from its corresponding gold WAV by at most one PCM16 step on that
file. This is a single-file check of the partial-codebook path.

This is an inference parity result for the final checkpoint. Training step
comparisons against all three original branches are in
[the training parity record](training-parity.md).

A self-contained release candidate was prepared from the same weights with the
model configuration embedded at `checkpoints/henac-300k.pth` (ignored by Git),
SHA-256
`978c7e9950b787b7a3673c198678c711cd5fab2fe766f4e41516125fc35a305e`.
It strictly loaded all 675 tensors. Using the installed wheel's `henac-infer`
command, its reconstruction of `001662_chunk_0.wav` was byte identical to the
regenerated legacy WAV. The public download URL is still pending.

For additional structural parity, the original `baseline_skipae` and
`entropy_ctrl` branches were each instantiated with the same small 32 kHz
architecture and random state as the consolidated core and mid stages.
After strictly loading the shared weights, both stages returned identical
code indices and zero maximum waveform error on a fixed 800-sample input.
This checks stage forward math without relying on unavailable trained
core and mid checkpoints.
